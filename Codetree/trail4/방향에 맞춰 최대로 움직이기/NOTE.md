## 한 줄 인사이트

각 칸의 방향으로 뻗은 모든 칸을 후보로 삼고, 숫자가 커지는 이동 경로를 모두 탐색해 최대 이동 횟수를 구한다.

## 문제 요약

시작 칸에서 현재 칸에 적힌 방향으로 이동한다. 그 방향의 직선 위에서 현재 숫자보다 큰 숫자가 적힌 칸으로 이동할 수 있을 때, 최대 몇 번 이동할 수 있는지 구한다.

## 현재 코드의 접근

`Node(id, r, c, w)`에 현재 숫자, 위치, 지금까지의 이동 횟수를 저장하고 큐로 탐색한다.

1. 시작 위치를 이동 횟수 0으로 큐에 넣는다.
2. 현재 칸의 방향을 읽고, 해당 방향으로 한 칸씩 나아가며 격자 안의 모든 칸을 확인한다.
3. 현재 숫자보다 큰 칸마다 이동 횟수 `w + 1`인 상태를 큐에 넣는다.
4. 새 상태를 만들 때마다 최대 이동 횟수를 갱신한다.

방향 배열은 1부터 위, 오른쪽 위, 오른쪽, 오른쪽 아래, 아래, 왼쪽 아래, 왼쪽, 왼쪽 위 순서이다. 입력 좌표는 1부터 시작하므로 배열 접근 전에 1을 뺀다.

## 왜 탐색이 끝나는가?

이동할 때마다 숫자가 반드시 커지므로 순환이 생기지 않는다. 한 경로에서 같은 칸을 다시 방문할 수 없으며 경로 길이도 유한하다.

같은 칸에 서로 다른 경로와 이동 횟수로 도착할 수 있다. 현재 코드는 이런 상태를 모두 큐에 넣는다. 단순히 방문 여부만 추가해 첫 방문만 남기면 더 긴 경로를 놓칠 수 있다.

## 복잡도와 개선

현재 코드는 칸마다 한 번만 처리하는 일반적인 BFS가 아니다. 큐에서 꺼낸 상태마다 한 방향의 최대 N - 1개 칸을 확인한다.

- 시간: `O(P × N)`. P는 큐에서 처리하는 전체 경로 상태 수이며, 경로 중복 때문에 지수적으로 커질 수 있다.
- 공간: `O(N² + Q)`. 격자 저장 공간과 최대 큐 크기 Q.

개선한다면 `dp[r][c] = 현재 칸에서 출발해 추가로 이동할 수 있는 최대 횟수`를 메모이제이션할 수 있다. 숫자가 증가하는 DAG이므로 각 칸을 한 번 계산해 시간 O(N³), 공간 O(N²)로 줄일 수 있다.

## 주의할 점

- 바로 옆 칸만 갈 수 있는 것이 아니다. 같은 방향의 더 먼 칸도 모두 후보이다.
- 중간에 현재 숫자보다 작거나 같은 칸이 있어도 직선 탐색을 중단하지 않는다.
- 시작 칸은 이동 횟수에 포함하지 않는다. 움직일 수 없다면 답은 0이다.
- 큐를 사용했지만 최단거리가 아니라 가능한 경로를 모두 열거하는 풀이이다.
