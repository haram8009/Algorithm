## 한 줄 인사이트

물로 이동하는 비용은 0, 빙하로 이동하는 비용은 1로 보면, 매시간 격자를 다시 탐색하지 않고 0-1 BFS로 각 빙하가 녹는 시간을 구할 수 있다.

## 접근

바깥 물과 연결된 `(0, 0)`에서 탐색을 시작한다. 물을 따라 이동하는 데에는 시간이 추가되지 않고, 빙하를 통과하려면 한 시간이 추가된다.

상태 `Node(r, c, t)`의 t는 해당 칸에 도달하는 시간이다. 인접한 물은 현재 시간에 탐색하므로 덱 앞에 넣고, 빙하는 다음 시간에 녹으므로 덱 뒤에 넣는다. 이 순서를 유지하면 시간이 작은 상태부터 처리된다.

빙하에 둘러싸인 내부 물은 바깥에서 길이 열리기 전까지 방문되지 않는다. 따라서 내부 물이 처음부터 외부 물처럼 빙하를 녹이는 오류도 피할 수 있다.

## 코드 흐름

1. 덱에 `(0, 0, 0)`을 넣는다.
2. 상태를 꺼내 이미 방문한 칸이면 건너뛴다.
3. 처음 처리하는 칸을 방문 처리한다.
4. 빙하라면 물로 바꾸고, 해당 시간에 녹은 빙하 수를 집계한다.
5. 인접 칸이 물이면 `offerFirst`로 같은 시간에, 빙하면 `offerLast`로 t + 1에 탐색한다.
6. 마지막 시간 t와 그 시간에 녹은 빙하 수 cnt를 출력한다.

## 마지막 시간의 개수 세기

빙하를 처리할 때 현재 기록된 시간과 같으면 cnt를 늘린다. 더 큰 시간이 나타나면 t를 갱신하고 cnt = 1로 초기화한다. 탐색 시간이 오름차순이므로 종료 시에는 마지막으로 녹은 빙하 수만 남는다.

## 복잡도

각 칸은 처음 꺼냈을 때 한 번만 확장하며 네 방향을 확인하므로 시간과 공간은 O(NM)이다. 방문 전에는 같은 칸이 여러 번 덱에 들어갈 수 있지만, 전체 삽입 수는 격자 간선 수에 비례한다.

## 주의할 점

- 일반 큐에 모두 뒤로 넣으면 이동 횟수 순서가 되어 비용 0과 1을 반영하지 못한다.
- 현재 코드는 덱에서 꺼낼 때 방문 처리한다. 넣는 순간 확정하면 더 이른 시간으로 도달하는 경로를 놓칠 수 있다.
- 시작점 (0, 0)이 외부 물이라는 입력 조건을 전제로 한다.
- `Comparable<Node>`는 현재 ArrayDeque 구현에서 사용되지 않는다. 순서는 덱 앞/뒤 삽입으로 결정된다.
